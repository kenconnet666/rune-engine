# rune-engine

用 TypeScript 写的浏览器游戏引擎，和用它做的第一个游戏《迷惘》。个人学习与娱乐项目，MIT 协议。

> 不盈一握之迷惘，由此孕育出邪念，爬过旷野，翻越山丘，播撒灾厄于长空。

《迷惘》是一个关于传染病怎样传播、又怎样被拦住的策略游戏：可以扮演攻方（病原体）或守方（防控），
一个人玩时另一方由电脑控制，也可以两个人各执一方。

它不是流行病学的模型，更不是医学建议：人口、经济是公开数据里的估计数，航线和海运是模型估的，
病原体的数值是照着原型的“性格”定的游戏取值。数据和素材的来源见 [docs/credits.md](docs/credits.md)。

## 游戏里有什么

- **一张真实的世界地图**：176 个国家和地区，各有人口、气候、密度、富裕程度；陆路、航线、海运三种路线。
- **攻守两方**：攻方攒变异点、换性状（传播途径、症状、能力），还有三个主动技能（外溢、激增、蛰伏）；
  守方有预算，在各地区安排措施（分三档，有预案，能一键推广到别的地区）、派应急队、做研究、赶疫苗、定疫苗先给谁。
  双方看到的不一样——攻方看真实的感染，守方只看得到上报的。
- **抉择与短期任务**：隔一阵子会碰上一件要拿主意的事，两个选项各有得失；手里总有一件做到了有奖励的小目标。
- **看得见的反馈**：地图可以换着看感染、传播数、措施压掉的传播、医疗挤兑、接种；做了什么、对面做了什么都有提示；
  结算时有评价、大事记，和对局结束才公开的真实数字。
- **十种病原体**：一种没有原型的“新发病原体”，九种以常见传染病为原型（流感、麻疹、霍乱、登革热、疟疾、结核、诺如、埃博拉、百日咳）；
  百科里有它们的公开资料和出处。
- **五章**：诗的五句各是一章，限定了条件和目标，也是教学的顺序，带引导提示。
- **两个人玩**：开房间、发邀请链接；能直连就直连，不能就经服务器中转；谁掉线了都接得回来。
- **存档与回放**：自动存档、八个存档位、导出导入、从头回放；有服务端时还有不用账号的云存档。
- **中文和英文**；标准和色觉友好两套配色；声音是现场合成的。

## 只面向最新的正式版 Chrome

渲染用 WebGPU，放在 Worker 里画（OffscreenCanvas）。不做旧浏览器的兼容，也不转旧语法。
桌面浏览器和手机横屏用同一套布局；手机上只在模拟的视口里核对过，没有在真机上试过。

## 结构

```
packages/            引擎，不知道任何具体游戏
  core               模拟内核：确定性的随机数与数学、时钟、命令与回放、状态哈希、Decimal 与日历日期
  net                主机与会话：主机持有唯一的真实状态，各方发命令、收自己能看到的部分；
                     走网络时消息的编码，联机房间和存档柜（云存档）的约定
  transport          浏览器这头和服务端打交道的部分：联机的连接（进房间、WebRTC 直连、直连不通时经房间中转）、
                     云存档的客户端
  edge               跑在 Cloudflare Workers 上的服务端：联机的房间、云存档的存档柜（各是一个 Durable Object 类）
  render             WebGPU 2D 渲染（不碰 DOM）：地区地图、色带、视野的坐标换算、点选；
                     照着显示列表画界面（自己画的那一套）；把主线程拍下来的界面贴到画面上的合成器
  input              手势：拖动、缩放、轻点、停留（鼠标、触屏、键盘同一套回调）
  audio              声音：设备解锁、分路音量、合成用的基本件
  runtime            把线程接起来：消息通道、画布尺寸、主机的计时循环、存在浏览器里的小东西
  stage              舞台：一张画布加画在画布里的几层界面，和画面同一帧合成；弹层的宿主、贴着锚点摆的层（见 docs/interface.md）；不认识具体的组件
  view               自己画的界面（见 docs/view.md）：节点树、样式、排版、命中都是自己的，不是网页元素；由 Vue 驱动，
                     排好版交给渲染线程用 WebGPU 画。现在是内核，之后界面都换到它上面
  kit                建在 view 上的一小套基础组件（主题、文字、按钮、卡片、页签、开关、滚动区域、代码块）
  ui                 游戏用的界面组件（TSX 编译与样式引擎、属性合并的约定用 vue-tsx-pro 的）；图标用 lucide
  components         组件库：从 vue-tsx-pro 复制来、在这边分叉着改，目标是整套能画进画布（见它的 UPSTREAM.md）；
                     游戏之后换到它上面，packages/ui 到时候删掉
  i18n               多语言：当前语言、各语言的文案、跟着语言走的数字与日期写法
apps/
  docs               组件库的文档站（从 vue-tsx-pro 的文档站复制来的）：整站放在一个舞台里，
                     可以画进画布（?stage=canvas）、也可以当普通网页看（?stage=dom），两种摆法对比着改
  lab                试验场：同一张大表格，网页元素和自己画的并排对比（挂载、更新、滚动）
  site               自己画的界面的文档站：整站画在一张画布里（用的是 view 和 kit），示例都是活的
  assets-build       构建时的素材处理：地理数据 → 地区网格
games/miwang/        《迷惘》
  sim                规则，只依赖 core：浏览器、Worker、Node 里算出逐位相同的结果；电脑对手也在这里
  content            数据：世界地图的地区，性状、科技、事件、病原体、章节各张表，内容的文案；批量对局的调数值脚本
  client             浏览器客户端：主线程是界面，主机和渲染各在一个 Worker 里
  server             部署到 Cloudflare 的那一个 Worker：联机的房间、云存档，部署时带上游戏的静态文件
scripts/             检查与核对：包的边界、下载体积的预算、无界面浏览器里的冒烟测试与性能核对
```

包之间只能从下往上依赖，`pnpm check:boundaries` 会检查；它还检查模拟相关的包里没有用
`Math.sin`、`Math.exp`、`Date.now` 这类在不同引擎或不同时刻结果不一样的东西——
同一局在 x64 和 ARM 上要算出逐位相同的结果，CI 里两种架构各跑一遍核对。

## 开发

需要 Node 24 和 pnpm（版本见 package.json 的 packageManager）。

```bash
pnpm install
pnpm dev            # 《迷惘》的开发服务器：http://localhost:5180
pnpm dev:docs       # 组件库的文档站：http://localhost:5181（右下角换“画进画布 / 普通网页”）
pnpm dev:lab        # 试验场：http://localhost:5183（自己画的界面和网页元素对比）
pnpm dev:site       # 自己画的界面的文档站：http://localhost:5185（整站画在画布里）
pnpm online         # 同上，再加本地的服务端（联机、云存档；wrangler 在本机模拟 Cloudflare，听 8787）
pnpm check          # 格式、lint、边界、类型、测试
```

改代码时页面怎么反应：

- 界面组件和样式：热更新，游戏不停；
- 模拟的规则：页面刷新，然后照着暂存的对局记录重放到刚才那一步接着走——同一局在新规则下会走成什么样，立刻看得到。

在无界面的 Chrome 里核对（用机器上已经装的 Chrome；先把游戏起起来）：

```bash
pnpm smoke          # 把游戏从头点一遍：菜单、设置、百科、开局、进化、换边、选地区、存档回放
pnpm smoke:chapters # 章节：目标、提示、打到分出胜负、下一章
pnpm smoke:online   # 两个页面一主一客，把联机走一遍
pnpm smoke:cloud    # 两台“设备”把云存档走一遍（要带服务端）
pnpm perf           # 量主线程卡不卡、渲染线程每帧花多久（--budget：超了线就报错）
node scripts/browser/lab.mjs --out=目录   # 试验场（先 pnpm dev:lab）：两种落地各量一遍，核对画得一样
node scripts/browser/site.mjs --out=目录  # 画布版文档站（先 pnpm dev:site）：每页走一遍，选中复制、滚动、换主题
pnpm check:budget   # 构建之后：下载体积的预算
```

调数值用批量对局：`node games/miwang/content/scripts/balance.ts 局数 攻方难度 守方难度`
（`PATHOGEN=all` 每种病原体各跑一遍，`CHAPTER=<id>` 按某一章的条件和目标打，`RULES='{…}'` 临时覆盖规则里的数）。

## 地图怎么操作

拖动平移；滚轮、触控板或双指捏合以指针为中心缩放；方向键、`+`、`-`、`0` 也行。
指针停在一个地区上显示它的名字，点一下选中、右侧出现详情和这一方能对它做的事；点海面取消选中。

## 章节

主菜单 → 章节。诗的五句各是一章（迷惘、邪念、旷野、山丘、长空），每章是限定了条件和目标的一局，也是教学的顺序：
攻方要在期限内做到这一章的目标，守方要拦到期限；每章都可以选扮演哪一方。打的时候左边有目标和进度，
到了该讲的时候会冒出一句提示。各章的条件和目标在 `games/miwang/content/src/tables/chapters.ts`。

## 两个人玩

主机在开房间的那位玩家的浏览器里，另一位经网络连过来：

1. 主人在主菜单点“联机”→“开一个房间”，把房间号或者邀请链接给对方；
2. 对方打开链接（或者在自己的主菜单“联机”里输入房间号）就进来了，扮演主人没选的那一方；
3. 两头能直连就直连（WebRTC，同一个局域网里走的就是内网），直连打不通的网络环境下消息经房间中转，
   对局照常，只是多绕一段路。界面上看得到现在走的是哪条路。

谁掉线了都能接回来：客人刷新页面会自己连回原来的位置；主人刷新页面会照着自动存档接上那一局，
房间还是原来那个，客人自动重连。对方掉线时时间会停下，主人可以等，也可以让电脑先接手。

联机要有服务端（`games/miwang/server`，一个 Cloudflare Worker；部署见 [docs/deploy.md](docs/deploy.md)）。
没有它的时候——`pnpm dev`、默认的构建——“房间”退化成同一个浏览器里的标签页互连，其余完全一样，开发和演示够用。
客户端用哪一种在构建时定：`vite --mode online` 用和页面同一个来源的 `/api`，
也可以用环境变量 `VITE_API_URL` 指到别处。地址里加 `?relay` 可以不试直连、只走中转（排查问题用）。

## 存档

正在打的这一局随时自动存在本机，关掉页面再打开可以接着打；另有八个存档位，记录能导出成文件、再导入、从头回放。

有服务端的时候还有云存档（主菜单 → 存档与回放 → 云端）。不用注册账号：设备生成一个同步码，
存档按这个码放在服务端；在另一台设备上填同一个码，看到的就是同一批存档。同步码就是钥匙，别发到公开的地方。
