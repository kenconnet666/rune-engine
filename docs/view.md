# 自己画的界面

界面不是网页元素：节点树、样式、排版、命中、画，都是我们自己的，只用到画布和 WebGPU。组件照常用 Vue 写。

为什么这么做：把网页元素画进画布（HTML-in-Canvas，见 [interface.md](interface.md)）做不到比网页更快——
它先把浏览器的样式、排版、绘制整套走一遍，再加上我们拍、画、合成的几步；而且那个接口只有新的 Chrome 有。
自己的节点没有这些包袱：同一张两万行的表，挂载、更新、滚动都比网页元素快几倍（数在最后）。
现在是第一步，只有一个内核和一张对比用的表；HTML-in-Canvas 那一套（`packages/stage`、`packages/components`、文档站）
还在，等这边够用了逐步换掉。

## 一帧是怎么出来的

```
主线程                                              渲染线程（Worker）
Vue 组件 ──→ 节点树 ──→ 排版 ──→ 显示列表 ──消息──→ 照着画（WebGPU）
              ↑                                       文字段画进图集（2D 画布）
        指针、滚轮（命中、事件、状态）
```

- **界面的逻辑和排版在主线程**，画在渲染线程：和浏览器自己的分法一样。必须用到网页的东西（输入法、剪贴板、
  无障碍）都在主线程，离逻辑最近；游戏的画面（地图、三维）也在渲染线程，界面是在它之后接着画的一层，同一帧出来。
- **不等下一帧**：树一变，这一轮事件处理完马上排版、马上把显示列表发过去，渲染线程下一帧就画上。
- **指针用 `pointerrawupdate`**（一到就发；`pointermove` 要攒到帧边上才发）。量过（160 Hz）：
  主线程自己画，输入到开画 4.6 毫秒；转给渲染线程，用 `pointermove` 是 10.0 毫秒（正好多一帧），
  用 `pointerrawupdate` 是 3.9 毫秒——跨线程不比主线程慢，而且主线程忙的时候渲染线程照样满帧。
  没有这个事件的浏览器（Safari）退回 `pointermove`。

## 东西在哪

| 位置                                   | 管什么                                                                     |
| -------------------------------------- | -------------------------------------------------------------------------- |
| `packages/render` 的 `view-types.ts`   | 约定：显示列表的格式、文字段、主线程发给渲染线程的消息                     |
| `packages/render` 的 `view-painter.ts` | 渲染线程里照着显示列表画：圆角矩形、边线、文字，一次画完；文字图集         |
| `packages/view` 的 `node.ts`           | 节点（`ViewNode`）和树（`ViewTree`）：样式、子节点、排版结果、变了没有     |
| `packages/view` 的 `style.ts`          | 样式有哪些、文字样式怎么往下传、认颜色、哪些变了要重排                     |
| `packages/view` 的 `layout.ts`         | 排版（弹性盒子的一小套），只重排变了的                                     |
| `packages/view` 的 `text.ts`           | 量文字有多宽                                                               |
| `packages/view` 的 `renderer.ts`       | 把 Vue 接到节点树上（`createViewApp`）；写 TSX 用的 `View`、`Text`         |
| `packages/view` 的 `events.ts`         | 命中、指针事件、指着 / 按着的状态、滚轮                                    |
| `packages/view` 的 `display.ts`        | 把排好的树列成显示列表（只列露出来的）；登记文字段                         |
| `packages/view` 的 `host.ts`           | 宿主：把一棵树接到一张画布上（尺寸、输入、什么时候刷新）                   |
| `packages/view` 的 `worker/`           | 只画界面的渲染线程（整页都是界面时用；有自己画面的把画的那一层接进自己的） |
| `apps/lab`                             | 试验场：同一张表，网页元素和自己画的并排比                                 |
| `scripts/browser/lab.mjs`              | 无界面浏览器里跑试验场：量数、核对两边画得一样、点选和滚动生效             |

## 怎么用

```tsx
import { createViewHost, Text, View } from '@rune-engine/view';
import { runViewRenderer } from '@rune-engine/view/renderer';

const App = _component(() => () => (
  <View style={{ flex: 1, padding: 16, backgroundColor: '#17181c', color: '#e6e6e6' }}>
    <View
      style={{
        padding: 8,
        borderRadius: 6,
        backgroundColor: '#2a2c36',
        hover: { backgroundColor: '#3b5bdb' },
      }}
      onClick={() => console.log('点了')}
    >
      <Text>一个按钮</Text>
    </View>
  </View>
));

const renderer = runViewRenderer(canvas); // 起渲染线程，画布交给它
const host = createViewHost(canvas, { send: renderer.send });
host.mount(App);
```

元素只有两种：`View`（盒子，放别的节点）和 `Text`（一行字，里面只放文字）。它们不是组件，就是元素的名字带上了属性的类型。
要拿到节点用 Vue 的 `ref`（`ref={(node) => …}`），节点上有 `scrollTo`、位置和大小。

## 样式

名字照着 CSS 起，现在只有一小部分：

- 排版：`flexDirection`、`width` / `height`、`min*` / `max*`、`flex` / `flexGrow` / `flexShrink` / `flexBasis`、
  `alignItems` / `alignSelf` / `justifyContent`、`gap`、`padding*`、`margin*`、`overflow`。
- 画法：`backgroundColor`、`borderRadius`、`borderWidth` / `borderColor`、`opacity`。
- 文字（往下传）：`color`、`fontFamily`、`fontSize`、`fontWeight`、`fontStyle`、`lineHeight`。
- 交互：`cursor`、`pointerEvents`、`hover`、`active`（指着、按着的时候另外加的样式）。

**和 CSS 不一样、要知道的：**

- 每个盒子都是弹性容器，默认**竖着排**、子节点横向撑满。
- `flexShrink` 默认是 0：放不下就溢出去，不会自己缩。要“占满剩下的地方”写 `flex: 1`（和 CSS 的 `flex: 1` 一个意思）。
- 长度只有像素；`lineHeight` 也是像素，不是倍数。
- 一行字不换行。超出盒子的靠盒子的 `overflow: 'hidden'` 裁掉。
- 一个节点整个在裁剪框外面时，它溢出到盒子外面的子孙也不画（眼下认了）。

样式对象尽量事先建好、大家共用：两万行不用建两万份，换没换也是按“是不是同一个对象”认的。

## 排版

弹性盒子的一小套：横排 / 竖排（不换行）、定宽定高、按份数伸缩、内外边距、间隔、两个方向的对齐。

只重排变了的：一个节点自己和子孙都没变、父节点给的大小和传下来的文字样式也和上回一样，整棵子树跳过。
改一个格子的字，重排的只有它到根那一条线上的节点（两万行的表里是几毫秒）。

## 文字

量和画都交给浏览器的文字引擎（2D 画布的 `measureText`、`fillText`，Worker 里也有），所以字距、中文、
系统字体、字体回退都是浏览器的，不用打包字体。

- **整段量、整段画**，不能一个字一个字来：英文有字距调整，量了相加的话四段里有一段差半个像素以上。
- 一段字（同一个字体、同一行里的一串）画进图集一次，之后只是贴图；图集里只存“有没有墨”，颜色是画的时候乘上去的。
- 新画进图集的只把那几行传给显卡。整张重传的话，连着滚动时每帧传几千万像素（试验里帧率掉了一半）。
- 现在是灰度的抗锯齿；网页元素在有的地方是彩色的亚像素，低分屏上看着略细一点。要做的话用双源混合。

## 指针和滚动

浏览器不知道节点在哪。页面只把“指针到了画布上的哪个位置”交进来，谁被点到、谁被指着、该滚哪个盒子都是自己算
（长列按位置二分，只看露出来的那些）。

事件照网页的习惯：`onClick`、`onPointerdown`、`onPointerup`、`onPointermove` 从被点到的节点往上冒，
可以 `stopPropagation`；`onPointerenter`、`onPointerleave` 不冒；点击落在按下和松开两处共同的最近祖先上。
`overflow: 'scroll'` 的盒子滚轮能滚，到头了交给外面的；`onWheel` 里 `preventDefault` 可以拦住。

滚动现在在主线程：改了位置，重列一遍显示列表（零点几毫秒）发过去。主线程卡住时它也跟着卡——
之后要搬到渲染线程里（多列一截备着、渲染线程自己挪）。

## 必须借网页的那几样

节点不是网页元素，有几件事只能借浏览器。逐样试过（无界面的 Chrome 157，输入法是模拟的；真输入法手打过，正常）：

- **输入法**：画布只听键盘事件的话，输入法的组字一个事件都收不到，中文打不了。
  Chrome、Edge 上把 `EditContext` 直接接在画布上就行，组字、上屏、字符位置都收得到，**不用输入框**；
  Firefox 还在做原型、Safari 没有，那两家要一个看不见的 `<textarea>`。
- **复制粘贴**：焦点在画布上按 Ctrl+C / Ctrl+V，`copy`、`paste` 事件照常收到。接了 `EditContext` 的画布在试验里
  收不到，要用剪贴板接口（读的时候浏览器会先问一次许可）。
- **无障碍**：画布上画的东西读屏看不到，没有不用网页元素的办法。最省事的是把元素放在 `<canvas>` 标签里面
  （不显示）：角色、名字进了无障碍树，Tab 走得到，回车、空格会触发点击。但它们量不到位置；要位置（放大镜跟随、
  触摸浏览）得用盖在画布上的透明元素。
- **页内查找、选中文字、网页翻译**：都看不到画布上的字。要么自己做选中和查找，要么在画布上盖一层透明的字
  （找得到、选得中、读屏看得到，代价是露出来的字都要有对应的元素）。

这几样都还没做（见下面）。

## 量出来的数

`pnpm dev:lab` 起试验场（http://localhost:5183，`?mode=view|dom&rows=2000`），
`node scripts/browser/lab.mjs --rows=2000 --out=目录` 在无界面的浏览器里两种落地交替着跑。

同一张订单表（7 列，一行一个状态标记），开发模式，160 Hz：

|                    | 2000 行：网页元素 | 2000 行：自己画 | 两万行：网页元素 | 两万行：自己画 |
| ------------------ | ----------------- | --------------- | ---------------- | -------------- |
| 挂载到出画面       | 962 毫秒          | 569 毫秒        | 8.5 秒           | 2.9 秒         |
| 改 200 格到出画面  | 50 毫秒           | 14 毫秒         | 129 毫秒         | 17 毫秒        |
| 连着滚，主线程帧率 | 121 帧/秒         | 146 帧/秒       | 38 帧/秒         | 142 帧/秒      |

自己画的那版渲染线程在 140～160 帧，每帧列的显示列表一百五十来项、零点几毫秒。两边画出来的表缩小后比，差 0.41%
（文字抗锯齿不一样；位置是对上的）。机器忙的时候数会差不少，看两边的比例。

## 还没做的

按打算做的先后：

1. 文字换行、省略号；绝对定位；网格排版、百分比。
2. 过渡和动画（在渲染线程里走）；滚动搬到渲染线程；阴影、渐变、图片、图标（矢量路径画进图集）。
3. 焦点和键盘；文字输入（`EditContext`）、选中、复制粘贴。
4. 无障碍用的那棵隐藏的元素树。
5. 样式后端：和组件库同一套接口（`css.create`）的样式写法落到这里的样式上；然后按层重写组件。
6. 游戏的界面换过来；HTML-in-Canvas 那一套拆掉。
