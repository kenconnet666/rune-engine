# 界面是怎么画的

界面是普通的网页元素（Vue 的 TSX 组件），但不是叠在画布上面由浏览器去贴，而是**画进画布**：
渲染线程把它和地图在同一帧里合成。用的是浏览器的 HTML-in-Canvas（Chrome 157 起）。

这样换来的：界面照常排版、照常响应鼠标键盘、读屏照常念得到，同时它成了画面的一部分——
可以整层过着色器（扫描线、错位、一块块显现），可以整层淡入、缩放、位移，这些都在渲染线程里逐帧算，
不重新排版，主线程忙不忙都不影响。

浏览器不支持、或者渲染那头出了事（显卡设备丢了）时，界面照老办法叠在画布上面：样子和操作一样，只是没有那些效果。

## 几样东西各在哪

| 在哪                                     | 做什么                                                                                     |
| ---------------------------------------- | ------------------------------------------------------------------------------------------ |
| `packages/render` 的 `ui-types.ts`       | 两头的约定：一层的画面、一层怎么贴（`UiMaterial`）、几种消息。不碰显卡的类型，主线程也用它 |
| `packages/render` 的 `ui-compositor.ts`  | 渲染线程这头：每层一张贴图，按次序贴到这一帧上；贴法的过渡在这里插值                       |
| `packages/stage` 的 `canvas-ui.ts`       | 主线程这头：把各层“拍”下来发给渲染线程，告诉浏览器各层画在哪（点击命中要用）               |
| `packages/stage` 的 `Stage.tsx`          | 舞台：一张画布加几层界面；管“搬进画布 / 搬回来”，给里面的组件提供层和贴法                  |
| `packages/stage` 的 `StageLayer.tsx`     | 使用方自己加的一层                                                                         |
| `packages/ui` 的 `Dialog.tsx`、`Tip.tsx` | 弹出类的组件：画在层里，不走浏览器的“顶层”                                                 |

## 层

舞台自带四层，从下往上：`world`（跟着世界走的东西：地名、标记）、`hud`（一直在的界面）、
`overlay`（对话框）、`tips`（提示气泡）。每层铺满舞台、自己不接收指针，里面的面板、按钮各自打开。

```tsx
<Stage
  world={<MapLabels />}
  onReady={(stage) => {
    /* 拿 stage.canvas 去建渲染线程，再 stage.connect(发消息的函数) */
  }}
>
  …一直在的界面…
</Stage>
```

渲染线程说“画面接上了”之后调 `stage.setLive(true)`，各层搬进画布；画面断了调 `setLive(false)` 搬回来。
搬的时候元素不重建，滚到哪、焦点在哪都留着。

**为什么要分层**：上下遮挡由层的先后决定；一层是一张贴图，贴法（`UiMaterial`）是整层的。
想让一块界面单独淡入、单独过效果，就让它单独成层：

```tsx
<StageLayer order={1.5} enter={{ from: { reveal: 0, scale: 1.04 }, ms: 900 }}>
  …结算的面板…
</StageLayer>
```

`order` 定上下（自带的四层是 0、1、2、3，写小数插在它们之间）。

层也可以**只有内容那么大**，放在舞台上的某个位置：

```tsx
<StageLayer fit="content" x={point.x} y={point.y} order={1.2}>
  …一个气泡…
</StageLayer>
```

小的、老在动的东西用它：重拍一层的代价跟面积走，而且只是挪位置的话根本不用重拍——位置是贴的时候才用的。
地图上跟着指针走的标注就是这样一层：指针每动一下它挪一次，别的层一次都不用重画。

## 一层怎么贴

`UiMaterial`：`opacity`、`x`、`y`、`scale`、`rotate`（绕画布中心）、`tint`（乘上去的颜色），和三个效果，各是 0–1 的一个数，可以叠：

- `scan`：扫描线、轻微闪烁和偏色
- `glitch`：横向错位加色散
- `reveal`：按噪声一块块显现（0 全没有，1 是原样）；亮边的颜色在建合成器时给

改贴法不用重拍那层界面。在舞台里的组件用 `useStage()`：

```ts
stage.material('hud', { scan: 0.55 }, 400); // 用 400 毫秒过渡过去
stage.pulse('hud', { glitch: 0.7 }, 450); // 闪一下，再回到原来的贴法（系统设了“减少动态效果”时不闪）
```

界面没画在画布里时这些调用什么都不做，所以只拿它们做锦上添花的事。位移、缩放、旋转会同步给命中测试：画在哪，就点在哪。

## 弹出类的组件

浏览器的“顶层”（`popover`、模态的 `<dialog>`）画不进画布，所以弹出类的组件不用它，改成把自己传送到舞台的某一层里，
遮挡和定位自己处理：

- **`Dialog`**：在 `overlay` 层，一层压暗的底加一个非模态的 `<dialog open>`。模态该有的事自己做：
  打开时 `world`、`hud` 两层设成 `inert`，焦点进对话框、关了还回去，Esc 和点外面能关。出现的样子可以用 `enter` 换。
- **`Tip`**：气泡在 `tips` 层。触发的元素写 `data-tip={id}`，舞台统一管什么时候出、摆在哪
  （默认在上方居中，放不下翻到下方，左右不出舞台）。

以后加下拉、菜单这类组件也照这个做法：传送到 `overlay` 或 `tips` 层，位置按触发元素的位置自己算。

## 要知道的几个性质

- **重拍一层，是把一整层重新画一遍**。层里任何一点变了都是这样，花的时间跟这层的像素数走，没有“只重画变了的那一小块”。
  所以采集讲节奏：一次只拍一层，轮流来；一秒里重画的像素有上限（`pixelBudget`，默认每秒 9000 万像素——
  1600×900 的窗口一秒能拍六十次，4K 的屏一秒十来次）。两种情况不等：还没有画面的层，和刚操作过界面的时候
  （按下、悬停要马上有反应）。
- 由此来的建议：**一直在动的东西不要放在一大层界面里**。循环的动画、每帧都变的读数会让那一整层每帧重画。
  要么交给贴法和着色器（整层的效果、过场），要么画在地图那头，要么把它单独分一层（一小块变，别的层不用重画）。
- 一层被藏起来（`display: none`、`visibility: hidden`）时，渲染线程那头它的画面会收掉。
- 一层头一回拍到之后，采集会隔一小会儿再补拍两次：层刚搬进画布的那一帧拍到的画面可能还停在某个过渡的半路上，
  而之后浏览器不再为它发通知——不补拍，界面上要是没有别的变化，那个半路上的样子就一直留在画面上。
- 带 `drawable` 的元素在画布里的排版位置没有意义，所以每层都铺满画布；层里面的东西照常用 CSS 排。
- `backdrop-filter` 在层里拿不到后面的画面（地图不在元素的背景里）。要模糊背后的东西得在合成器里做，现在没有。

实测的数（Chrome 157，真窗口，160 Hz 的屏，10 倍速、两层界面都在变）：

| 情况                               | 4 秒里主线程的帧数 | 超过 50 ms 的帧 |
| ---------------------------------- | ------------------ | --------------- |
| 界面叠在画布上面，1600×900         | 555                | 3               |
| 画进画布，不讲节奏（两层同帧拍）   | 183                | 7               |
| 画进画布，现在的节奏               | 533                | 1               |
| 界面叠在画布上面，3840×1854        | 388                | 0               |
| 画进画布，一秒拍三十来次           | 224–327            | 14–17           |
| 画进画布，现在的节奏（一秒十来次） | 413                | 0               |

这些“长的帧”主线程并没有被卡住（最长的一个任务三十毫秒），是这一帧在等合成。

## 没验证的

- 中文输入法的候选框位置（无界面的浏览器里只试过直接插入文字）。
- 别的显卡上重拍一层要多久：上面的像素预算是在一台机器上量出来的。
- 手机上的表现。
